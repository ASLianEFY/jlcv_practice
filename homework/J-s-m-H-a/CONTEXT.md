## 1. 任务

- 仓库：`jlcv_practice`（NUDT 自瞄培训，第 1 周作业）
- 作业原文：

  > 识别视频中的绿球，并使用箭头标注其运动方向和速度变化。把代码写在 `homework/name/` 下。

- 标注规则（作业原文）：
  - 箭头方向表示小球的运动方向。
  - 箭头长度表示速度大小：箭头越长速度越快，越短速度越慢。

## 2. 视频事实（已用 OpenCV 核实）

| 项目 | 值 |
|---|---|
| 文件 | 仓库根目录 `homework.mp4` |
| 分辨率 | 1280 × 720 |
| 帧率 | 30 fps |
| 时长 / 帧数 | 15.77 s / 473 帧 |
| 编码 | H.265 视频 + AAC 音频 |
| 拍摄方式 | 手持，镜头持续运动 |

场景内容：

- 木纹桌面。
- **绿球**：画面中唯一的绿色球体，半径约 55–85 px（随镜头远近变化）。
- **绿色圆柱**：与球同色，是检测的主要干扰项。
- 红色圆柱、白色圆柱、红色方块、白色方块（均非检测目标）。

颜色统计（说明为什么必须用几何形状区分）：

| 帧 | 对象 | H 均值 | S 均值 | V 均值 |
|---|---|---|---|---|
| 0 | 球 | 83.6 | 238.5 | 181.3 |
| 0 | 圆柱顶 | 83.9 | 224.8 | 192.7 |
| 40 | 球 | 71.8 | 198.2 | 105.3 |
| 40 | 圆柱顶 | 76.1 | 203.4 | 86.1 |

球与圆柱的 HSV 高度重合，**颜色阈值无法区分两者**，必须依赖圆度/长宽比/下方绿色占比/时间连续性。

关键结论：**绿球相对桌面是静止的，画面中的位移来自镜头运动。**

核实方法：每 3 帧检测一次球心（共 157 个采样），得到：

- 原始图像位移中位数约 **40 px / 0.1 s**；
- 用非绿色区域（桌面与其它积木）估计桌面平面单应矩阵并补偿镜头运动后，绿球残差中位数约 **3 px / 0.1 s**；
- 15.7 s 累计漂移约 **(6, 39) px**，与视差和单应累积误差同量级；
- 全片没有手进入画面，球与其它积木的相对位置始终不变。

## 3. 语义约定（本作业采用的口径）

- "运动方向 / 速度"指**图像视运动**（apparent image motion），即球心在画面坐标系中的运动，不扣除镜头运动。
- 不实现相机运动补偿；在 `README.md` 和本文件中明确说明球在世界坐标中静止，箭头反映的是镜头视运动。
- 速度为图像速度，单位 `px/s`；由 Kalman 滤波的速度状态给出。
- "速度变化"通过箭头长度体现，不额外绘制速度曲线；同时导出逐帧速度 CSV，并在画面左上角显示当前数值与状态。
- 这是第 1 周作业，采用经典 CV 方法（HSV 分割 + 轮廓筛选 + Kalman 跟踪），不使用深度学习。

## 5. 术语表

| 术语 | 含义 |
|---|---|
| 绿球 / green ball | 画面中唯一的绿色球体，检测目标 |
| 绿色圆柱 / green cylinder | 与球同色的圆柱，主要干扰项，必须排除 |
| 图像视运动 | 目标在图像坐标系中的位移，包含镜头运动的影响 |
| 世界运动 | 目标相对桌面的真实位移；本视频中约为 0 |
| 速度 | 图像速度大小，单位 px/s |
| 检测率 | 全片中 `status=detected` 的帧数占比（不含 predicted） |
| hits / misses | 连续有效检测次数 / 连续丢失次数；hits ≥2 才确认轨迹 |
| ROI | 正常跟踪时围绕 Kalman 预测点的检测区域，半径 `2.5r_smooth` |
| 欧氏硬门控 | 关联的硬门限：`max(2.5r, 1.5|v|dt+10)`；与 ROI 同尺度 |
| Mahalanobis 排序 | 在通过硬门控的候选中按 `d²` 取最小；`d²>9.21` 标记 recovery，下次预测放大 Q |
| 丢失兜底 | 检测失败时只做 KF 预测，最多 5 帧；之后进入 `lost` 并全图重捕获 |
| Kalman 状态 | `[cx, cy, vx, vy]`，匀速模型；观测为球心 `[cx, cy]` |
| 自适应 Q | recovery 帧后临时放大过程噪声，抑制快速晃镜/反向时的滞后 |
| 镜头反向 | 画面运动方向突变；匀速 KF 会预测错方向，必须靠欧氏硬门控保住真球 |
| 箭头长度映射 | `L = clamp(0.25 × speed, 20, 220)` px，球心锚定，箭头最后绘制 |
| status | CSV 状态：`detected` / `predicted` / `lost` |

## 6. 已确定的技术决策

- 语言与依赖：Python 3.12 + OpenCV（`opencv-python-headless`）+ numpy。
- 代码结构：`main.py` 仅 CLI；实现拆分到 `greenball/` 包（config、segmentation、detection、tracking、speed、annotation、export、pipeline），每个模块带 docstring；测试文件开头标明功能与覆盖范围。
- 忽略规则：虚拟环境用仓库根 `venv/`（upstream 根 `.gitignore` 已忽略）；生成物与缓存规则放在 `homework/J-s-m-H-a/.gitignore`，**不修改根 `.gitignore`**，避免与 upstream 的 add/add 冲突。
- 分割：HSV 绿色阈值 → 3×3 开运算（避免大核闭运算粘连）→ 支持 ROI。
- 候选筛选：面积（自适应）、双圆度指标、长宽比、下方绿色占比、半径一致性；不使用上方绿色占比；HoughCircles 半分辨率兜底。
- 跟踪：Kalman 匀速模型（4 状态）；**欧氏门限（2.5r）为硬门控**，Mahalanobis 用于排序与 recovery 标记；半径一致性；hits/misses、ROI、丢失外推 5 帧、全图重捕获、重捕获重置 KF、自适应 Q。
- 镜头反向修复：实测约 401–406 帧画面运动反向，硬 Mahalanobis 门限会误杀真球；已改为欧氏硬门控 + Mahalanobis 排序（单独提交 `fix(week1): 放宽关联门限以处理镜头反向`）。
- 速度：KF 后验速度；首帧 v=0；累计 3 次 update 或 `σ_v < 300 px/s` 前不画箭头；显示 clamp 2000 px/s；CSV 保留原始值。
- 标注：球心箭头（方案 a），`L = clamp(0.25×v, 20, 220)`；绘制顺序为圆框 → 标签 → 箭头 → 文字；预测帧灰色虚线；可选 `--trail`（默认关闭）。
- 输出：`annotated.mp4`、`speed.csv`（含 `r` 与 `status`）、6 张抽样帧、`contact_sheet.png`；`--debug` 输出掩码/候选/ROI；全部放 `output/` 且不提交。
- 测试：pytest；U1–U6 单元测试 + I7 合成视频 + I8 真实视频 + I9 12 帧人工真值（误差 ≤10 px）；检测率 ≥95%，最长连续丢失 ≤5 帧。
- 验证结果（2026-10-19）：473 帧全部 detected（100%），0 predicted/lost，最长连续丢失 0；速度中位 375.4 px/s、p90 637.7 px/s；44 项测试通过；12 帧人工十字线核对通过。
- 交付顺序：文档 → 检测/跟踪 → 速度/标注/导出/测试；三个里程碑均需人工审核。
- Git：小步提交；每个里程碑 push 一次；**全部完成且经确认后才创建 PR**；PR 完成后再合并 upstream。
