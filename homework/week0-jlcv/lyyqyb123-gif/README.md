# week0-jlcv 邓晧元    作业：绿球检测与卡尔曼滤波运动估计

## 作业要求

识别 `homework.mp4` 中的绿球，并用箭头标注其运动方向和速度变化：

- 箭头方向 = 小球的运动方向
- 箭头长度 = 速度大小（越长越快，越短越慢）

本版本在完成上述要求的基础上，进一步用卡尔曼滤波实时估计小球的
位置、速度、加速度，并给出下一帧的位置预测。

## 运行环境

- Python 3.8+
- OpenCV（`opencv-python`）
- NumPy

安装依赖：

```bash
pip install -r requirements.txt
```

运行（在仓库根目录）：

```bash
python3 homework/week0-jlcv/lyyqyb123-gif/detect_green_ball.py
```

默认读取仓库根目录的 `homework.mp4`，输出到脚本所在目录：

- `output_annotated_kalman.mp4`：带标注的视频
- `trajectory_kalman.csv`：逐帧位置、速度、加速度数据

也可以手动指定路径和滤波参数：

```bash
python3 detect_green_ball.py \
    --input /path/to/homework.mp4 \
    --output result.mp4 --csv result.csv \
    --jerk-std 1500 --meas-std 3
```

`--show` 可以实时显示处理窗口（按 `q` 退出），用于查看逐帧的实时效果。

## 算法流程

1. **颜色分割**：BGR 转 HSV，用绿色范围 `(35,60,50) ~ (90,255,255)` 做阈值；
2. **去噪**：5×5 形态学开运算 + 闭运算；
3. **候选筛选**：保留面积 400~40000、圆度 > 0.5、宽高比 0.70~1.40 的轮廓。
   绿色圆柱的面积更大、宽高比偏离 1，因此被排除；用图像矩计算质心；
4. **卡尔曼滤波**：
   - 状态向量 `x = [px, py, vx, vy, ax, ay]^T`，采用匀加速运动模型；
   - 预测：`x = F·x`，`P = F·P·Fᵀ + Q`，其中 Q 由 jerk 标准差构造；
   - 关联：在本帧候选中选择距离预测位置不超过 120 px、且形状得分最高的目标；
   - 更新：`K = P·Hᵀ·(H·P·Hᵀ + R)⁻¹`，并用 Joseph 形式更新协方差，保证数值稳定；
   - 短暂丢失时按预测位置滑行；连续丢失超过 15 帧后重新捕获并重置滤波器；
5. **实时运动学估计**：
   - 速度 `speed = |v|`；
   - 切向加速度 `a_t = (v·a)/|v|`，表示速率的变化率（正=加速，负=减速）；
   - 加速度模 `|a|`，包含方向变化带来的法向加速度；
6. **单遍因果处理**：第 t 帧只使用第 0~t 帧，检测、滤波、绘制、写视频和
   CSV 一次完成，可以直接用于实时场景，不需要第二遍读取视频；
7. **可视化**：
   - 洋红色圆圈：卡尔曼滤波估计位置；
   - 绿色小十字：本帧检测到的原始质心（测量值）；
   - 青色十字：对下一帧的预测位置；
   - 箭头：速度方向，长度随速度自适应缩放；
   - 箭头颜色：红色=加速，蓝色=减速，黄色=速度基本不变；
   - 文字显示当前速度、切向加速度和加速度模；
   - 右下角绘制最近 10 秒的滚动速度曲线。

## 结果

- 视频：1280×720，30 fps，共 473 帧（约 15.8 s）
- 检测率：**100%**（473/473 帧）
- 处理速度：约 **107 fps**，约为实时的 **3.6 倍**（测试环境为 Docker +
  OpenCV 4.5.4 + NumPy 1.21.5，具体数值与机器性能有关）
- 滤波位置与最近原始检测点的偏差：平均 **1.18 px**，中位数 0.88 px，
  p95 为 3.40 px，最大 6.86 px
- 速度：平均约 **400 px/s**，p95 约 **778 px/s**，最大约 **948 px/s**
- 切向加速度：均值约 **426 px/s²**；加速度模均值约 **1042 px/s²**

> 与旧版（15 帧中心滑动平均）相比，本版本的速度整体偏大。这是因果滤波的
> 正常现象：旧版的中心平滑会用到未来帧，在视频末段快速运动时位置平均滞后
> 约 45 px；卡尔曼滤波则紧跟当前检测点（偏差约 1 px），因此速度更接近画面
> 中的真实运动。同理，实时估计的加速度会比非因果平滑的结果更“抖”，所以
> 箭头变色阈值设为 600 px/s²，以减少颜色频繁跳变。

## CSV 字段

`trajectory_kalman.csv` 每帧一行，表头为：

```
frame,time_s,x,y,vx,vy,ax,ay,speed_px_s,accel_t_px_s2,accel_mag_px_s2,detected
```

- `x, y`：卡尔曼滤波估计的球心坐标（像素）
- `vx, vy`：估计速度（像素/秒）
- `ax, ay`：估计加速度（像素/秒²）
- `speed_px_s`：速率 `|v|`
- `accel_t_px_s2`：切向加速度 `a_t`
- `accel_mag_px_s2`：加速度模 `|a|`
- `detected`：1 表示该帧有检测并完成更新，0 表示按预测滑行

## 文件说明

| 文件 | 说明 |
|---|---|
| `detect_green_ball.py` | 主程序（检测、卡尔曼滤波、跟踪、标注） |
| `output_annotated_kalman.mp4` | 生成的标注视频 |
| `trajectory_kalman.csv` | 每帧的位置、速度、加速度数据 |
| `requirements.txt` | Python 依赖 |

可调参数集中在 `detect_green_ball.py` 顶部（HSV 范围、面积/圆度阈值、
`MAX_JUMP`、`MAX_LOST`、`ACCEL_THRESHOLD`、速度曲线窗口等）；
`--jerk-std` 和 `--meas-std` 可在命令行覆盖滤波器的过程噪声与测量噪声。
