## 二、算法流程

```
读帧 → BGR转HSV → 颜色阈值分割(绿色mask) → 形态学开/闭运算
    → findContours → 三重筛选(面积+宽高比+圆形度) → 锁定绿球球心
    → 光流估计相机全局运动 → 投影上一帧球心 → 求「球相对场景」的位移
    → 位移×帧率 = 瞬时速度 → EMA 平滑 → 画箭头/尾迹 → 写出视频
```

### 1. 为什么不能"取绿色最大的区域"

画面里除了绿球，还有一个**颜色完全相同但面积更大的绿色圆柱**。如果只取"绿色最多的部分"，一定认错。所以本作业在颜色分割之后加了**形态学处理 + 形状判别**：

| 特征 | 绿球 | 绿色圆柱 |
|---|---|---|
| 外接矩形宽高比 W/H | ≈ 1.0（0.97~1.03） | 0.58 ~ 0.82（细长） |
| 圆形度 `4πA/P²` | 0.68 ~ 0.75 | 0.55 ~ 0.65 |
| 面积 | 约 10,000 ~ 21,000 | 约 22,000 ~ 32,000 |

再叠加时序约束（与上一帧球心距离 < 250px、面积比在 0.35~2.8 之间），避免误跳。

### 2. 为什么要做相机运动补偿

视频是**手持拍摄**，镜头一直在动。直接拿相邻帧球心位移当速度，测出来的主要是"镜头在动"，箭头方向会变成镜头移动方向。因此先用稀疏光流估出全画面的整体运动，再把上一帧球心投影到当前帧坐标系，差值才是球真实的位移。

实测（473 帧）：相邻帧位移中位数 **11.40 px → 0.64 px**。

### 3. 速度平滑与箭头

- 速度用指数滑动平均（α = 0.30）平滑；目标丢失时按 0.8 衰减
- 箭头长度 = 速度 × 0.70，限制在 30~260 px；速度低于 25 px/s 不画箭头
- 颜色随速度由绿变红（300 px/s 为全红），同时画最近 90 帧的运动尾迹
